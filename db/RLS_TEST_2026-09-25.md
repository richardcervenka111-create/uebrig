# RLS-Selbsttest, Projekt UebrigBern (tegbrfloehfblkmjawha), 25.09.2026

Ausgeführt als Migration mit drei Testbenutzern (Küche, freigegebener Abnehmer, nicht freigegebener
Abnehmer), Rollenwechsel per `set local role` + `request.jwt.claims`, Testdaten am Ende gelöscht.

| Test | Ergebnis |
|---|---|
| anon sieht Angebote / Profile | 0 / 0 |
| nicht freigegebener Abnehmer sieht Angebote / Profile | 0 / 1 (nur eigenes) |
| nicht freigegebener Abnehmer schaltet sich selbst frei | blockiert |
| nicht freigegebener Abnehmer reserviert per RPC | blockiert (not_allowed) |
| freigegebener Abnehmer sieht offene Angebote / Profile | 1 / 2 (eigenes + Küche) |

| Küche legt Angebot für fremde Küche an | blockiert |

| eigenes Profil (Name/Telefon) ändern | OK |
| eigenes `approved` setzen | blockiert |
| eigene Rolle auf admin setzen | blockiert |

Gefunden und behoben: `profiles_update_own` fragte in WITH CHECK die Tabelle `profiles` ab und
lief in eine Rekursion (jede Profiländerung wäre fehlgeschlagen). Ersetzt durch die
SECURITY-DEFINER-Helfer `i_am_approved()` und `my_role()`. Supabase Security Advisor danach:
keine Warnung zu Tabellen; RPC-Funktionen sind absichtlich für `authenticated` ausführbar, für `anon` entzogen.

Bekannte Grenze: freigegebene Abnehmer können über die API Betrieb, Kontakt und Telefon jeder Küche
mit offenem Angebot lesen (die App zeigt Telefon erst nach Reservation). Das ist im geschlossenen,
vom Admin freigegebenen Netz gewollt; wer es enger will, entfernt `phone` aus `profiles_select_counterpart`
und liefert die Nummer über eine RPC nach der Reservation.

## Nachtrag 25.09.2026, nach 002_hardening.sql (20/20)

Auslöser: Architektur-Review fand drei Lücken in 001 (Küche konnte `status` direkt setzen; korreliertes EXISTS in
`profiles_select_counterpart`; Helfer nicht als `(select …)`). Warum sie durchkamen: der erste Selbsttest prüfte nur den
Abnehmer (kein UPDATE-Recht), nie die Küche gegen ihre eigene UPDATE-Policy. Zaun: Trigger `offers_guard_update`
+ dieser Testlauf (`db/002_rls_test.sql`, als Migration ausführbar, räumt sich selbst auf).
